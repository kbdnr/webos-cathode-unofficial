# Cathode Cinema for webOS (unofficial)

A homebrew LG webOS app that wraps [cathodetv.com](https://cathodetv.com/) for the TV: full-height player,
side or overlay chat, and remote-control mappings. The player host changes often, so the app reads
the live site on launch (and every 30 min) and follows whatever player iframe it currently embeds.

## How it works

```
launch ──► show cached/fallback stream immediately
       └─► discover current embeds (swaps player/chat only if they changed)
             1. XHR cathodetv.com, regex the <iframe> srcs        (needs webOS to allow CORS)
             2. else load it in a hidden iframe; userscript posts the HTML back
             3. else localStorage cache
             4. else CATHODE_CONFIG.fallback in app/js/config.js
```

`app/webOSUserScripts/userScript.js` is injected by webOS into every frame, including cross-origin
ones. Inside the **player** frame it starts the stream by clicking the host's poster card (retrying
until the host's player script is ready, then reporting `needs-start` so the app can prompt), finds
the largest `<video>` including inside open shadow roots (ok.ru's player is a web component),
handles play/pause and an optional fill-the-frame mode, and reports resolution. Inside the **chat**
frame it scrolls on request. Players grab keyboard focus once they start, so the player frame
forwards OK, Play/Pause, ▲▼, Back, colour keys and Info to the app; the chat frame forwards only
Back, colour keys and Info, keeping OK and arrows for typing.

## Remote

| Key | Action |
|---|---|
| OK / Play / Pause | Start / pause. The stream normally starts by itself; if it doesn't, a prompt says to press OK (unmutes if autoplay was muted) |
| Red | Show/hide chat |
| Yellow | Chat beside the player ↔ overlaid on it |
| Green | Rediscover stream now |
| Blue | Settings (stream override URL, chat nickname, width, text scale) |
| ▲ ▼ | Scroll chat |
| Info | Toggle "fill" mode in the player frame (hides host chrome; remembered per host) |
| Back | Close settings / exit |

## Build & install

The IPK is built by webpack with [@webosbrew/webos-packager-plugin](https://github.com/webosbrew/webos-packager-plugin)
(`webpack.config.js`): `app/js/app.js` is bundled to ES5 `js/main.js`, the HTML/CSS/icons/userscript are
copied, `appinfo.json` gets its version from `package.json`, and everything emitted is packed into the IPK.

```sh
npm install
npm run build         # -> dist/com.unofficial.cathodetv_<ver>_all.ipk (+ .manifest.json)
npm run watch         # unminified rebuild + new IPK on every save
npm test              # discovery parser against a saved snapshot + edge cases
npm run check-live    # what discovery picks from the live site right now
```

Install `dist/*.ipk` with webOS Dev Manager / Homebrew Manager, or with the webOS CLI on a TV in
[Developer Mode](https://www.webosbrew.org/devmode) registered as `tv`:
`npm run deploy && npm run launch` (`npm run inspect` for remote DevTools; `TV=<device>` to override).

To release a new version, bump `version` in `package.json` and rebuild (`npm version patch && npm run build`).
`npm version` also syncs `app/appinfo.json` (via the `version` script). The installer treats a higher version as an update.

`com.unofficial.cathodetv.manifest.json` is the per-app manifest the Homebrew Channel repo format uses
(with the IPK's sha256). You only need it if you self-host a repo; fill in `iconUrl`/`sourceUrl` in
`webpack.config.js` first.

Quick layout checks work in a desktop browser (`npm run build && npm run serve`, then open
http://127.0.0.1:8765), but there's no userscript there and CORS blocks the fetch, so it falls back to
the cached/fallback stream.

## When the site changes hosts

1. `npm run check-live`. If it prints the new player, nothing to do; the app will follow it.
2. If the new host needs help (poster click, banners), add an entry to `HOST_HOOKS` in the userscript.
3. If the site stops using an iframe entirely (e.g. a JS-built player), extend `parse()` in
   `app/js/discover.js` and add a fixture/test.
4. Update `fallback` in `app/js/config.js` so fresh installs start on a working stream.

## Still to verify on a real TV

- Whether the direct XHR is allowed (otherwise discovery runs through the probe iframe, which takes a few seconds longer).
- That the userscript is injected into cross-origin frames on your webOS version.
- Embed compatibility on older TVs: webOS 3.x and 4.x run Chromium 38–53, which modern players may not support.
  All app code is ES5 for this reason.

Placeholder icons are generated by `npm run icons`. Please ask Cathode's maintainers before submitting
this app to the Homebrew Channel repo.

## Troubleshooting: "-501 server certificate cannot be trusted"

webOS shows this when a frame loads an HTTPS host the TV doesn't trust. The app checks each host
with a quiet fetch before framing it, and shows which one failed instead (Blue → `TLS:` line).
This check needs webOS 4.0 or later; webOS 3.x has no `fetch`, so hosts are loaded unchecked.

1. Check the TV's date/time is set automatically. A slow clock makes every new certificate invalid.
2. Open each host in the TV's own web browser to confirm: https://cathodetv.com, https://ok.ru,
   https://minnit.chat. Their roots are ISRG Root X1 (Let's Encrypt), HARICA RootCA 2015 and
   GlobalSign Root CA respectively, and older firmware may lack the first two.
3. Without root, a firmware update is the only way to get newer roots.

### Certificate fix for rooted TVs

Settings → **Install certificate fix** runs `ca/cathode-ca.sh install` as root through Homebrew
Channel's `exec` service. It adds the current Mozilla root list (`ca/mozilla-roots.pem`, from
[curl's extract](https://curl.se/docs/caextract.html)) to every store the TV's TLS clients read:

| Store | Used by |
|---|---|
| `/etc/ssl/certs` (bundle + hash links, incl. `trusted_cas.crt` if present) | OpenSSL clients, **incl. WebAppMgr** (confirmed on webOS 4.x) |
| `/var/palm/jail/com.webos.app.browser/etc/ssl/certs` | the built-in browser |
| `/usr/share/ca-certificates/sdp/sdp-ca.pem` | LG platform services |
| `/etc/pki/nssdb` (via `certutil`, only if both exist; absent on webOS 4.x) | NSS-based clients |

Firmware files are never modified: each store gets a read-only overlay whose top layer holds merged
copies. **Remove certificate fix** unmounts everything and deletes the hook and
`/var/lib/webosbrew/cathode-ca`. It needs webOS 3.5 or later (kernel overlayfs support).

WebAppMgr, which runs all web apps, reads the CA bundle **once at startup**, and it starts long
before Homebrew Channel runs boot hooks (about 30 s into boot on webOS 4.x). So:

- After installing or removing, choose **Restart web engine**. This closes all web apps, including
  this one, and reloads the home screen; reopen the app afterwards. A reboot alone is not enough.
- The boot hook (`/var/lib/webosbrew/init.d/cathode-ca`) runs `cathode-ca.sh boot`, which remounts
  the overlays and then restarts WebAppMgr. Expect the home screen to reload once, shortly after
  startup. Layers are only rebuilt when the bundle, the script or a stock store changes.

Over SSH: `sh /media/developer/apps/usr/palm/applications/com.unofficial.cathodetv/ca/cathode-ca.sh status`
(the app path may be under `/media/cryptofs/apps/...` instead, depending on how it was installed),
and the last boot run's log is in `/var/lib/webosbrew/cathode-ca/last.log` (`build.log` for the last
layer rebuild). `ca/diagnose.sh` (also in the IPK) prints a read-only report of the TV's certificate
stores and web engine processes.

```sh
npm run test:ca     # install/apply/uninstall against a fake old-TV store in a privileged
                    # Alpine container with real overlay mounts (needs podman or docker)
npm run update-ca   # refresh ca/mozilla-roots.pem (checksum-verified), then bump version + build
```

The approach and store list follow throwaway96's
[setup-cert-overlay.sh](https://gist.github.com/throwaway96/bb31a17562eec4d8325020dee8c7e6b5).
